# Drift 0.6.0 — Seeding limits, completion notifications, CSP hardening

**Date:** 2026-06-10
**Status:** Approved (scope set by project audit; owner asked for direct implementation)

## Goal

Close the three biggest gaps found in the 2026-06-10 project audit:

1. **Seeding limits** — Drift currently seeds forever; there is no way to stop
   sharing automatically.
2. **Download-complete notifications** — finishing a download is silent unless
   the window is open.
3. **CDN/CSP hardening** — the frontend loads `@tauri-apps/api` from jsdelivr at
   runtime with `csp: null`; the app cannot boot offline and a remote script has
   full IPC access.

Non-goals (explicitly out of scope for 0.6.0): per-torrent seeding overrides,
per-torrent speed limits, RSS/watch folders, streaming, localization.

## 1. Seeding limits

### Behavior

- Two new **global** settings, both `0 = unlimited` (the default, preserving
  today's behavior):
  - **Seed ratio limit** (`seed_ratio_limit: f64`) — stop seeding when
    `uploaded / total_size` reaches the limit. `total_size` is the denominator
    (not `downloaded`) so torrents whose data pre-existed on disk don't divide
    by zero or report absurd ratios.
  - **Seed time limit, minutes** (`seed_time_limit_mins: u32`) — stop seeding
    after this much wall-clock time since the torrent first finished.
- When either limit is reached the torrent is **engine-paused** and its
  persisted state set to **Completed**. Files are untouched; the UI already has
  a Completed state, so no new frontend states are needed.
- **Force start bypasses limits.** A record with `forced: true` is never
  auto-stopped — this is the "seed anyway" escape hatch, consistent with how
  `forced` already bypasses the queue cap.

### Data model

- `TorrentRecord` gains `completed_at: Option<i64>` (`#[serde(default)]`, ms
  epoch). Set once, on the first observed transition into
  `seeding`/`completed`, in the existing 1 Hz state-transition task in
  `main.rs`. Old `state.json` files load with `None` (limit clock starts from
  the upgrade, which is the safe interpretation).

### Enforcement

- New module `src-tauri/src/seeding.rs` with a **pure function**:

  ```rust
  pub struct SeedFacts { pub uploaded: u64, pub total: u64,
      pub completed_at: Option<i64>, pub now_ms: i64, pub forced: bool }
  pub fn should_stop(facts: &SeedFacts, ratio_limit: f64, time_limit_mins: u32) -> bool
  ```

  Rules: `forced` → never. Both limits 0 → never. Ratio limit > 0 and
  `total > 0` and `uploaded as f64 / total as f64 >= ratio_limit` → stop.
  Time limit > 0 and `completed_at` is `Some(t)` and
  `now_ms - t >= time_limit_mins * 60_000` → stop. Either condition suffices.
- Called from the 1 Hz progress task in `main.rs` for updates whose label is
  `seeding`: on `should_stop` → `engine.pause(...)`, set record state
  `Completed`, persist. The next poll tick reports the engine-paused finished
  torrent as `completed`, which matches the persisted state.
- Manual resume of a limit-stopped torrent: the existing **Force start** menu
  item (offered for paused/queued) is the supported path; it sets `forced`,
  which exempts the torrent from enforcement.

### Settings UI

- New "Seeding" group in the Settings tab: *Seed ratio limit (0 = unlimited)*
  and *Seed time limit, minutes (0 = unlimited)*, mirroring the existing
  numeric-input rows.

## 2. Download-complete notifications

- New dependency `tauri-plugin-notification = "2"`; plugin registered in the
  builder; `notification:default` added to `capabilities/default.json`.
- New setting `notify_on_complete: bool`, default **true**
  (`#[serde(default = ...)]` so old configs load).
- Fired from the existing state-transition detection in `main.rs`: when a
  record moves from `Downloading`/`Stalled` to `Seeding`/`Completed` (i.e. a
  real download finished — not a restart re-labeling an already-finished
  torrent), show a Windows notification: title **"Download complete"**, body =
  torrent display name. Errors are best-effort and ignored.
- Settings UI: a "Notify when a download completes" switch in the Behavior
  group.

## 3. CDN/CSP hardening

- `tauri.conf.json`:
  - `app.withGlobalTauri: true` — Tauri injects its API as `window.__TAURI__`;
    no CDN, no bundler, keeps the no-build-step ethos.
  - `app.security.csp` set to:
    `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src ipc: http://ipc.localhost`
    - `'unsafe-inline'` in `style-src` is required by the inline `style="..."`
      attributes the renderer generates; there are no `<style>` tags, so Tauri
      won't inject style hashes (which would void `'unsafe-inline'`).
    - Tauri automatically appends hashes for the inline theme `<script>` in
      `index.html`/`toast.html`, so they keep working under `script-src 'self'`.
    - `connect-src ipc: http://ipc.localhost` is what the IPC layer uses on
      Windows.
- `src/main.js` and `src/toast.js`: replace the two/three jsdelivr imports with
  destructuring from `window.__TAURI__` (`core.invoke`, `event.listen/emit`,
  `window.getCurrentWindow`). Local module imports (`icons.js`, `list-ops.js`)
  are unchanged; both files stay valid ES modules so the `node --check` CI step
  still passes.
