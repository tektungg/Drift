# Drift 0.6.1 — Robustness patch

**Date:** 2026-06-10
**Status:** Approved (scope chosen from the post-0.6.0 audit; design confirmed by owner)

## Goal

A patch release hardening the things that matter now that 0.6.0 is
auto-updating to real users. No new features — failure paths only.

1. **Corrupt state/settings no longer silently wipes data.**
2. **Release builds write a log file** so field issues are diagnosable.
3. **Drop the unused devtools permission** from the production capability set.

SemVer: **PATCH** (0.6.0 → 0.6.1) — robustness only.

## 1. Corrupt-file recovery

Today both stores do `serde_json::from_slice(..).unwrap_or_default()`
([state.rs:41](../../../src-tauri/src/state.rs), [settings.rs:86](../../../src-tauri/src/settings.rs)),
so a half-written or corrupted JSON silently resets to empty — and the next
flush overwrites the only evidence.

New module `src-tauri/src/persist.rs` with one helper:

```rust
pub fn load_json_or_recover<T: serde::de::DeserializeOwned + Default>(path: &Path) -> T
```

Rules:
- File missing → `T::default()` (normal first run).
- File reads + parses → the parsed value.
- File exists but **fails to parse** → rename it to
  `<filename>.corrupt-<epoch_ms>.bak`, log `warn!`, return `T::default()`.
  The timestamp keeps successive corruptions from clobbering each other.
- File exists but can't be **read** (locked/IO error) → log `warn!`, return
  `T::default()` **without** renaming (don't destroy a file we couldn't read).

Wiring:
- `state.rs`: replace the `if path.exists() { read.unwrap_or_default() } else
  default` block with `load_json_or_recover::<PersistedState>(&path)`.
- `settings.rs`: keep the "write defaults when the file is missing" behavior;
  only the parse path changes:
  ```rust
  let inner = if path.exists() {
      load_json_or_recover::<Config>(&path)
  } else {
      let c = Config::default();
      std::fs::write(&path, serde_json::to_vec_pretty(&c)?)?;
      c
  };
  ```

## 2. File logging

Replace `tracing_subscriber::fmt::init()` in `main.rs` with an `init_logging`
that layers:
- A **daily-rolling file** at `<data_dir>/Drift/logs/drift.log` via
  `tracing-appender` (new dep), non-blocking. The `WorkerGuard` is stored in a
  `static OnceLock<WorkerGuard>` so it lives for the process (dropping it would
  silently stop the writer).
- **Plus stdout in debug builds only** (`#[cfg(debug_assertions)]`), preserving
  today's `cargo tauri dev` console output.
- Level via `EnvFilter` (honors `RUST_LOG`), defaulting to `info`. Requires the
  `env-filter` feature on `tracing-subscriber`.

`init_logging(&data_dir)` is called at the top of `main()`, before the builder,
and after computing `app_data_dir()`.

## 3. Drop devtools permission

Remove `core:webview:allow-internal-toggle-devtools` from
`capabilities/default.json`. Grep confirms no frontend code calls a
toggle-devtools command, and debug-build devtools are unaffected (they come from
the debug build, not this permission).

## Release chores

- Bump `0.6.0` → `0.6.1` in `tauri.conf.json`, `Cargo.toml` (+ `Cargo.lock`),
  `package.json`.
- CHANGELOG `## [0.6.1]` with `### Fixed` (corrupt-file recovery, logging) and
  `### Security` (devtools permission removed).

## Testing

- `persist::load_json_or_recover` unit tests (tempdir): missing → default;
  valid → parsed; corrupt → default **and** a `.corrupt-*.bak` exists **and** no
  live file remains; unreadable case is covered by the parse-vs-read split.
- Existing `state.rs`/`settings.rs` tests stay green (they already cover legacy
  loads and round-trips).
- Full suite: `cargo test --locked`, `node --check`, `node --test`.
- Manual: corrupt `state.json` by hand → app starts empty, a `.bak` appears, and
  `logs/drift.log` records the warning.
